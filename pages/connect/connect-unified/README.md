# 커넥트 통합 시뮬레이터

- PRD ID: HAU-1 / Draft / 목표 출시일 미정
- 목적: 기존 4.2 병원 웹의 스타일을 유지하면서 커넥트에서 통합 업무·환경설정을 체험한다.
- 공개 경로: `/out/connect-unified.html`
- 백엔드 배포: **N/A**. 네트워크 호출 없는 프론트 전용 가상 시안.

## 체험

| 구분 | 화면·동작 |
|---|---|
| As-is (기본) | 기존 진료항목 예약 3탭·관리·운영 설정을 재현. 실제 서버와 연결하지 않음 |
| To-be (선택) | 웹 메뉴: 대시보드 / 진료 현황 / 진료실 관리 / 진료항목 / 진료실 운영 설정 |
| 진료 현황 | 3가지 유형 합치기, 상태·유형·진료실·오늘 필터, 검색·정렬·페이지 전환, 상세 모달 |
| 처리 | 내원확인(진료항목 제외), 병원취소·사유, 실제 진료완료 확인, 확정대기 예약 확정 |
| 프로그램 설정 | 트레이 → 환경설정. 기본 비연동 → 차트 선택 → 브릿지 설치 모사 → 장애·복구 |
| 결과 확인 | 굿닥 상태 저장 / 차트 전달·응답 / 환자 안내를 모의 처리 로그에서 구분 |
| 오류 검증 | 서버 오류, 취소 저장 실패 후 입력 유지, 차트 끊김 후 전달 재시도 |

## 원본 코드 대조

- 병원 웹: 기존 레이아웃·GRAY/BLUE 토큰, 예약 목록·상세 카드·취소 사유 선택 패턴을 재사용한 축약 재현.
- 데스크: 기존 대시보드의 오늘 예약 신청·진료 완료·진료 취소, 공지사항 구성. 숫자는 이 시안의 가상 예시이며 운영 집계 구현과 같다고 주장하지 않음.
- 취소 사유 원본 선택지: 일정 불가 / 담당 의료진 부재 / 진료항목 확인 필요 / 환자 정보 확인 필요 / 기타 병원 사정. 직접 입력은 To-be에서만 추가.
- 예약실패·확정대기는 ‘처리 필요’에 구분. 실패를 완료나 취소로 치환하지 않음.
- 자동 종료는 실제 완료·취소와 구분하며 변경 액션 없음.
- 연결 장애 중 내원확인은 자동 재전달하지 않고 차트의 현재 상태 확인 필요로 구분한다. 취소 재시도도 최신 내역 확인 후 모사한다.
- 진료완료의 차트 전달 규격은 확인 필요. 차트 성공으로 표시하지 않고 보류. 확인된 취소·내원확인만 전달·응답을 모사.
- 환자에 대한 취소 사유 공개 범위·문구·허용 상태와 실제 저장/동기화 계약은 정식 출시 전 검토 대상.

```sh
npm run proto:preview
```

서버·차트·파일 설치·환자 알림 없음. 가상 데이터만 사용하며 개인정보를 입력하지 않는다. 이전 `desk-unified` 시안은 유지한다.
